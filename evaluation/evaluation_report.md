## 7. Remaining limitations

* **Identifiers that exist nowhere in participant-visible data.** `audit_record_6645` (case_18) and `audit_record_5569` (case_20) appear only in `sample_output.csv`; `account_004` (case_04) has no activity row or evidence row. The pipeline cannot emit ids it cannot observe, so those three sample rows can never match exactly. The same limitation applies to 91 of the 518 hidden-set predictions that contain no `security_service` verification step (no audit record for the user is present at or before `audit_at`).
* **Chain linking is statistical for unanchored cases.** A completed case that consists only of an absent account, an audit record and an anonymized analytics profile has no identity-bearing resource to anchor on; its account is chosen by the learned phase model plus the optimal assignment. 21 of the 518 requests are flagged "among N equally plausible deletion events" in the run notes and may be wrong.
* **Hand-built scenarios.** The twelve screenshot/PDF cases rely on OCR (Apple Vision, cached) and on catalog links; the correct answers for their account ids and secondary artefacts cannot be validated beyond the ten public hand-built samples.
* **Heuristic intent classifier.** Language coverage is en/es/pt/fr/ja/ko plus explicit negations; it matches all 32 public requests and isolates 10 non-deletion requests in the 518, but an unseen phrasing could be misclassified. No LLM fallback is used.
* **No hidden-set accuracy is claimed.** All accuracy numbers above are on the 32 public samples, which were also used while developing the pipeline (the `Exact rows after` column shows that tuning). The synthetic tests are independent of the dataset but were written by the same team.
